منبع‌ها

فایلچه چیزی تعریف می‌کند
WebService1.0_Setup_Help.pdfساختن یوزر API، روشن و خاموش کردن سرویس، و صفحهٔ تست ورود.
WebService1.0_Usage_Help.pdfفهرست رسمی شیءها و عمل‌ها. ۴۴ صفحه. الگوی آدرس، توکن، و جدول خطا.
راهنمای استفاده یک کتابخانهٔ نمونه را نام می‌برد: https://github.com/tcdent/php-restclient. این کتابخانه API دلتاسیب نیست. فقط نمونهٔ کد PHP برای فرستادن درخواست است. الگوی آدرس رسمی داخل همان PDF این است: https://Server_IP:1043/1.0/Object/. شمارهٔ نسخه در مسیر، 1.0 است.

دو در جدا

در رسمی REST پورت ۱۰۴۳. شیء در مسیر است، مثل /1.0/user/. توکن با Api_Key ساخته می‌شود و آن کلید، SHA-512 رمز API است، نه خود رمز. درخواست‌های بعدی توکن را در هدر Authorization: Bearer می‌گذارند. جواب JSON است. وضعیت ۲۰۰ یعنی موفق.
صفحهٔ تست، راهنمای راه‌اندازی /test/webservice/api/restfull/test.login.php. اینجا فیلدها Api_Username و Api_Password هستند. رمز خام است، نه هش. خروجی همان توکن و مدت اعتبار است. جهان بیت از همین صفحه توکن می‌گیرد، نه از /1.0/auth/.
صفحهٔ تست روی خود دلتاسیب، عمل‌های REST را به https://127.0.0.1:1043/1.0/ می‌رساند. پورت ۱۰۴۳ از بیرون در دسترس نیست. برای همین ورکر به صفحهٔ تست همان سرور حرف می‌زند و صفحهٔ تست با API محلی حرف می‌زند.

دستورها و صفحهٔ راه‌اندازی

از راهنمای راه‌اندازی. این‌ها API مشترک نیستند. روشن و خاموش کردن خود وب‌سرویس روی سرور دلتاسیب‌اند.

نامکاربرد
pak.www.api.startبعد از ساختن یوزر API، وب‌سرویس را روشن می‌کند. از SSH خود دلتاسیب اجرا می‌شود.
pak.www.api.debugاگر تست ورود خطا داد، دیباگ API را روشن می‌کند.
pak.www.api.stopاگر وب‌سرویس لازم نیست، برای امنیت خاموش می‌شود.
test.login.phpصفحهٔ تست. یوزر و رمز API را می‌گیرد و توکن نشان می‌دهد. جهان بیت همین را از داخل ورکر صدا می‌زند.
یوزر API در دلتاسیب از مسیر Reseller و Operator، نوع Api ساخته می‌شود. PermitIP فهرست کلاینت‌های مجاز است. SessionTimeout عمر توکن است. ApiDebug دیباگ همان یوزر است. رمز با ChangePass جدا از ساخت یوزر تنظیم می‌شود. این رمز همان Secret ورکر است و داخل اپ نیست.

شرح هر عمل

auth / gettoken

POST به /1.0/auth/. فیلد الزامی: Api_Username و Api_Key. کلید، SHA-512 رمز است. عمل: gettoken. جواب موفق: token و SessionTimeout به ثانیه. PDF می‌گوید توکن را یک بار بگیرید و تا خطای باطل شدن، همان را برای بقیهٔ درخواست‌ها نگه دارید. جهان بیت این توصیه را روی گوشی اجرا نمی‌کند. هر خواندن، توکن تازه داخل ورکر می‌سازد و همان‌جا رها می‌کند.

user / list

GET به /1.0/user/. فهرست کاربر، یا با Filter فقط یک شرط. فیلدهای قابل انتخاب: User_Id, Username, Name, Family, Address یا ستاره برای همه. LimitFrom پیش‌فرض ۰ و LimitCount پیش‌فرض ۱۰۰. Filter با عملگرهای مقایسه، like، and و or ساخته می‌شود. جهان بیت فقط فیلدهای شناسه و نام را می‌خواند، Filter را روی یک Username می‌گذارد و سقف را ۵ می‌گذارد، بعد ردیف غریبه را دور می‌ریزد.

user / creditinfo

GET به /1.0/user/. وضعیت سرویس، حجم و زمان همان کاربر. Filter در این عمل الزامی است. بقیه مثل list سقف و شروع دارد. معنی فیلدهای جواب در بخش فیلدهای حجم است. این همان چیزی است که اپ به‌عنوان بسته نشان می‌دهد.

user / add

POST. ساخت کاربر. الزامی: Username، Password، و شناسه‌های Visp و Center و Supporter و Status و Reseller. اگر آن شناسه‌ها در دلتاسیب تعریف نشده باشند PDF می‌گوید مقدار ۱ بگذارید. Name و Family اختیاری‌اند. جواب موفق: status = 1. نکتهٔ PDF: بعد از ساخت، اول وضعیت کاربر تعریف شود و بعد سرویس به او اضافه شود. جهان بیت این عمل را نمی‌فرستد.

user / delete

DELETE. حذف با Username یا User_Id. اگر هر دو بیاید، نام کاربری اولویت دارد. جواب موفق: status برابر ۱. جهان بیت این عمل را نمی‌فرستد.

user / edit

PUT. ویرایش کاربر موجود. Username الزامی است. می‌شود رمز، نام، فامیلی، تلفن، موبایل، ایمیل، آدرس، کد ملی، تاریخ تولد و شناسه‌های ریسلر و visp و مرکز و پشتیبان را فرستاد. صفر در شناسه‌ها یعنی خالی. برای پاک کردن موبایل PDF می‌گوید یک فاصله بگذارید. جواب موفق: status برابر ۱. جهان بیت این عمل را نمی‌فرستد.

user.status / currentstatus

GET. وضعیت فعلی یک کاربر با Username یا User_Id. جواب: Status_Id و Status_Name. جهان بیت این شیء را صدا نمی‌زند. وضعیت سرویس را از ServiceStatus داخل creditinfo می‌خواند.

user.status / add

PUT. گذاشتن یک وضعیت روی کاربر. Username یا User_Id، به‌علاوه Status_Name یا Status_Id. جواب موفق: status برابر ۱. جهان بیت این عمل را نمی‌فرستد.

service / list

GET به /1.0/service/. فهرست سرویس‌هایی که در دلتاسیب تعریف شده‌اند، نه سرویس وصل‌شده به یک مشترک. فیلدها: Service_Id، ServiceName، Description، Price، ServiceType، ISEnable، UserChoosable، ResellerChoosable. Filter و سقف اختیاری است. جهان بیت کاتالوگ بسته را از این API نمی‌گیرد.

radius / list

GET. کاربران آنلاین روی RADIUS. Field در نمونهٔ PDF فقط Username است. Filter اختیاری است. سقف پیش‌فرض ۱۰۰. جهان بیت آنلاین بودن دستگاه را از روتر محلی می‌خواند، نه از این عمل.

radius / disconnect

DELETE. قطع یک نشست آنلاین. Filter الزامی است. نمونهٔ PDF: RUsername='a'. جواب موفق: status برابر ۱. جهان بیت قطع اتصال را از این API نمی‌زند.

user.payment / list

GET. پرداخت‌های یک کاربر. User_Id و Field الزامی‌اند. فیلدها شامل شناسهٔ پرداخت، نوع، مبلغ، مانده، شماره و تاریخ چک، نام و کد شعبه، توضیح، پایانه و ارز است. جهان بیت این فهرست را نمی‌خواند.

user.payment / add

POST. ثبت پرداخت. الزامی: User_Id، Currency_Id، PriceINCurrency، ExchangeRate. نوع پرداخت یکی از Cash، Cheque، Pos، Deposit، Other، TAX. تاریخ Persian یا Gregorian. فیلدهای چک و بانک اختیاری‌اند. جواب موفق: status برابر ۱. جهان بیت پرداخت ثبت نمی‌کند.

user.service.base / list

GET. سرویس‌های پایهٔ وصل‌شده به یک کاربر. Username یا User_Id. Filter و سقف اختیاری. PDF برای جواب موفق status برابر ۱ نوشته است. جهان بیت این فهرست را جدا نمی‌خواند.

user.service.base / add

POST. وصل کردن یک سرویس به کاربر. الزامی: User_Id و Service_Id. PayPrice اختیاری است. PayPlan یکی از PrePaid یا PostPaid. جواب موفق: status برابر ۱. جهان بیت سرویس وصل نمی‌کند.

user.service.base / cancel

PUT. لغو با User_ServiceBase_Id، یعنی شناسهٔ همان سرویس فعلی کاربر. جواب موفق: status برابر ۱. جهان بیت لغو نمی‌کند.

user.param / add

POST. افزودن یک پارام. الزامی: ParamItem_Id، TableName، TableId. TableName یکی از User، Service، Visp، Center، Server است و TableId شناسهٔ همان سطح است. ParamStatus یکی از Passthrough-Yes، Passthrough-No، Disable. Value مقدار پارام است. شناسه‌ها در بخش پارام‌ها هستند. جهان بیت پارام نمی‌نویسد.

فیلدهای جواب creditinfo

اسم‌ها همان PDF است. گروه فقط برای خواندن است.

گروهفیلدها و کاربرد
سرویسServiceStatus فعال یا null. ServiceName نام سرویس. StartDate و EndDate شروع و پایان. Period طول دوره. CurrentDT ساعت سرور. ISFairService اگر Yes باشد سرویس منقضی است. FairMikrotikRate پهنای باند در حالت Fair. UPFairStatus وضعیت Fair.
هدیهUser_Gift_Id، GiftEndDT، GiftTrafficRate، GiftTimeRate، GiftExtraTr حجم هدیه به بایت، GiftExtraTi، GiftMikrotikRate، GiftStopOnTrFinish اگر Yes باشد با تمام شدن حجم هدیه خود هدیه هم قطع می‌شود.
ترافیک سرویسSTrA کل، STrU مصرف، STrR مانده. ETr اضافه. ReturnTr برگشتی. Y سال، M ماه، W هفته، D روز، با همان پسوند A و U و R. ServiceFreeTrU و ServiceBufferTr در ابتدای جدول PDF آمده‌اند.
زمانSTi و ETi و YTi و MTi و WTi و DTi با A و U و R. واحد ثانیه. STiR برابر UL یعنی نامحدود.
واقعیRealReceiveTr دریافت واقعی، RealSendTr ارسال واقعی، RealUsedTime زمان واقعی. BugUsedTr و BugUsedTi مصرف باگ. FinishUsedTr و FinishUsedTi مصرف وقتی IP از نوع finish بوده.

آنچه کد جهان بیت واقعاً صدا می‌زند

مسیرکجا دیده شدهکار
/test/webservice/api/restfull/test.login.php راهنمای راه‌اندازی، و ورکر گرفتن توکن با یوزر و رمز API. توکن از ورکر خارج نمی‌شود.
/test/webservice/api/restfull/test.user.creditinfo.php کد ورکر. اسم این فایل در دو PDF نیست فرم تست که Object و Action و Filter را به API محلی 127.0.0.1:1043/1.0/ می‌رساند. ورکر از همین یک صفحه هم creditinfo می‌خواند هم list.
test.user.list.php فقط توضیح داخل کد پروژه، نه PDF صفحهٔ فهرست تست. استفاده نمی‌شود، چون فیلتر را به API نمی‌رساند. list از همان صفحهٔ creditinfo با Action=list فرستاده می‌شود.
/1.0/ و بقیهٔ شیءها راهنمای استفاده از اینترنت روی دامنهٔ ورکر بسته است. ورکر این مسیر را به دلتاسیب جلو نمی‌فرستد.
جمع: مستند ۱٫۰ شانزده عمل دارد. جهان بیت از آن میان فقط دو خواندن را، آن هم برای یک نام کاربری، از پشت صفحهٔ تست اجرا می‌کند: creditinfo برای حجم و list برای نام. ساخت، ویرایش، حذف، پرداخت، قطع RADIUS و نوشتن پارام در این مسیر وجود ندارد.
